## 4. Verified non-issues (checked against the amalgamation, no action needed)

- **Multi-`sqlite3_step` after DONE / MISUSE per SQLite version**: the wrapper never relies on version-dependent step-after-DONE behavior — `tryExecuteStep()` synthesizes `SQLITE_MISUSE` itself when `mbDone` (`Statement.cpp:208-211`) without calling SQLite, so the 3.6.23.1 auto-reset semantics never come into play. `executeStep()`/`exec()` after DONE throw as tested (`Statement_test.cpp:87,187`).
- **`sqlite3_step(NULL)` on a moved-from statement** is defined: `vdbeSafetyNotNull` returns `SQLITE_MISUSE_BKPT` for a NULL Vdbe, so `tryExecuteStep()` on a moved-from `Statement` returns `SQLITE_MISUSE` and `executeStep()` throws (message is the slightly misleading "needs to be reseted", but no UB).
- **Bind return codes**: every `sqlite3_bind_*` result goes through `check()` → throws on non-OK. Bind index 0 or negative yields `SQLITE_RANGE` from SQLite and throws (this is also what makes STMT-11 a messaging issue only). Verified by tests binding invalid indices.
- **`SQLITE_TRANSIENT` vs `SQLITE_STATIC`**: `bind()` text/blob consistently use `SQLITE_TRANSIENT` (copy), `bindNoCopy()` consistently `SQLITE_STATIC` with documented caller-lifetime contract (`Statement.cpp:112-153`); `bindNoCopy(std::string&&)` is `= delete`d in all three name/index forms (`Statement.h:185,283,384`) preventing dangling temporaries. Correct.
- **`bind(aIndex, (const char*)nullptr)`** is defined behavior: per the C API, a NULL third argument to `sqlite3_bind_text` binds SQL NULL. No guard needed.
- **`isColumnNull` before `executeStep()`**: both overloads call `checkRow()` first (`Statement.cpp:250-262`) → clean throw; tested (`Statement_test.cpp:49-52,84,770-777`).
- **`reset()` not clearing bindings** is explicitly documented (`Statement.h:92` "Calling reset() does not clear the bindings (see clearBindings())", plus the `clearBindings()` doc block) and extensively tested (`Statement_test.cpp:286+`, repeated "reset() without clearbindings()" blocks). `tryReset()` clearing `mbHasRow`/`mbDone` before calling `sqlite3_reset` (even when reset re-throws the deferred step error, test `:191-193`) is intended semantics.
- **int64/uint32 conversions**: `bind(uint32_t)` → `sqlite3_bind_int64` preserves the full unsigned range (STMT-09, re-verified); no `uint64_t` overload exists so there is no silent sign-flip overload trap.
- **`getColumnDeclaredType()` does NOT require `SQLITE_ENABLE_COLUMN_METADATA`**: `sqlite3_column_decltype` is core API; only `getColumnOriginName()` needs the macro and it is correctly `#ifdef`-gated in both header (`Statement.h:578-589`) and cpp (`Statement.cpp:271-278`). (It would only vanish under `SQLITE_OMIT_DECLTYPE`, which no build file in this repo sets.) NULL decltype (expression columns / non-SELECT) is guarded and throws (`Statement.cpp:308-316`).
- **Column-name map staleness across rows**: result column names cannot change row-to-row within one prepared program, so the build-once map is sound for normal use; the only staleness path is schema-change auto-reprepare (that specific gap is STMT-16).
- **Moved-from safety of the other raw-handle accessors**: `sqlite3_errcode(NULL)`/`sqlite3_extended_errcode(NULL)` return `SQLITE_NOMEM`, `sqlite3_errmsg(NULL)` returns the static "out of memory" string, `sqlite3_bind_parameter_count(NULL)` returns 0 (`sqlite3.c:95488-95491`), `sqlite3_reset(NULL)` returns `SQLITE_OK`. All defined — `getChanges()` (STMT-13) is the sole exception.
- **`prepareStatement()` error path leaks nothing**: on failure `sqlite3_prepare_v2` sets `*ppStmt` to NULL per the C contract; the throw happens before any `shared_ptr` wraps the handle. The `static_cast<int>(mQuery.size())` nByte cast shares STMT-05's theoretical >2 GB truncation but a >2 GB SQL *text* is not a realistic input; not filed separately.
