## Recommended Review Order (most critical first)

1. **U2 Statement** — highest complexity and highest blast radius; the prepare/step/reset state machine and bind matrix underpin every other data-path unit. A defect here propagates everywhere.
2. **U1 Database** — root object owning the connection handle and the riskiest concrete code (manual binary header parsing, raw file I/O, encryption keys, extension loading). Highest combined importance + security surface.
3. **U6 Savepoint** — freshly modified in the current HEAD commit (destructor exception-safety + rollback bookkeeping); new dual-flag logic is the most likely place for a just-introduced regression, and coverage of the new path is thin.
4. **U3 Column** — broad client exposure through cast operators and shared-statement lifetime coupling; subtle truncation/lifetime edges with lighter coverage than Statement/Database.
5. **U8 Header-only helpers** — public template API (VariadicBind/ExecuteMany) with pack-expansion ordering subtleties and a large untested type/arity space; Assertion macro feeds every destructor.
6. **U4 Backup** — moderate blast radius but notable coverage gap (only the main-DB happy path is tested; BUSY/LOCKED/partial-page branches are not).
7. **U5 Transaction** — simple and important, but low risk; quick pass to confirm commit/rollback flag logic and destructor safety.
8. **U7 Exception** — small, fully covered, low risk; verify null-handle and error-code handling.
9. **U9 Build/CI tooling** — no runtime blast radius but should be checked for CMake/meson flag drift and workflow permission/secret hygiene; untested except via CI.
10. **U10 Examples** — lowest priority; nothing depends on them, purely illustrative, only worth a glance for outdated/unsafe patterns.
